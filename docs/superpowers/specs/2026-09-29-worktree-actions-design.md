# Worktree cleanup actions design

## Purpose and scope

Extend the existing terminal dashboard so a user can remove selected worktrees and prune broken worktree records. Keep discovery, verdicts, and action rules in a UI-independent core. The first action release focuses on cleanup; copying paths, opening folders or editors, creating worktrees, and switching worktrees are outside this slice.

This builds on the read-only dashboard and the cleanup flow in `PROPOSAL.md`. The current `Safe` verdict uses local Worktrunk facts only. Merged PR lookup and live-session detection remain separate later work. Until then, locks and agent markers block removal because the dashboard cannot prove they are stale. A row marked `Review` may be removed only through an explicit, itemized confirmation.

## Selection and terminal flow

- `Space` toggles the focused row in the main table. `a` selects all currently visible `Safe` rows; repeating it clears those selections. Selection is keyed by worktree ID and survives sorting, grouping, and filtering. A refresh drops selections for rows that disappeared and never silently adds newly discovered rows. Rows with a lock, agent marker, Git operation, conflict, unknown local status, or broken worktree cannot be selected; trying says why.
- Enter (or `x`) prepares removal of the selection, or of the focused row when nothing is selected. Selecting a `Review` row with Space is its explicit opt-in; `a` never selects one. There is no separate review screen: a confirm dialog opens over the dimmed table. It lists each worktree and its size, states the total, names every row whose uncommitted or untracked changes would be discarded, and names rows the fresh check skipped and why. Unmerged branches are kept unless the user presses `D`; process reaping is off unless the user presses `e`. The dialog states both and ends with its answer keys. `y` or Enter starts removal; `Esc` cancels without running a write command. Enter is ignored for the first 400 ms the dialog is open, so pressing it twice cannot delete anything.
- (An earlier version used a full-screen review with per-row decisions, then a final summary. It had four steps for a routine cleanup, so a single confirmation replaced it; the naming of discarded changes and skipped rows is what carries the confirmation.)
- Removal runs in the background. Confirmed rows leave the table at once, and focus moves to the nearest remaining row. A progress line above the footer counts through every queued row, names the one being removed, and shows how many were not removed. Rows that fail or are skipped come back with their reason, and the rest of the table stays usable. New removals can be confirmed while one runs; each batch queues and runs after the previous one. Pruning waits until no removal is running. `Esc` (once nothing else is left to clear) or quitting stops after the current Worktrunk command completes; it never interrupts a running removal. When the batch ends, a message reports removed and failed rows and the measured free-space change, removed rows are hidden until the rescan of the affected repositories completes, and failed rows keep the reason in their details.
- Enter on a focused `Broken` row, with nothing selected, prunes its repository. Because `git worktree prune` applies to the entire repository, the confirm dialog states how many records `git worktree prune --dry-run --expire=now --verbose` would prune. Confirmation runs the same command without `--dry-run`, then rescans that repository.

## Core action service

Add a UI-independent action service next to the dashboard service. Its public operations prepare a removal plan from selected worktree IDs, execute a plan with per-row choices, prepare a prune plan for a repository, execute that prune plan, and subscribe to action progress. It owns all permission checks and command construction; terminal code cannot directly invoke Git or Worktrunk. The dashboard remains the source of visible rows and refreshes after a completed action.

Preparing a removal plan fetches fresh `wt -C <repo> list --format=json` data for every affected repository. It matches each worktree by repository and absolute path, confirms `worktree.main === false`, and compares path, branch, HEAD commit, local changes, lock, marker, operation, and prunable state with the selected snapshot. It also runs `git -C <worktree> status --porcelain --ignored` for a file preview, omitting common dependency/build directories from the display but retaining the fact that ignored files exist. If any fact changed, that row is blocked with a reason and needs a new preview.

Immediately before each removal, the service rechecks that row, including its uncommitted and untracked files, and refuses to run if its identity or safety facts changed since the preview. The service never removes a main worktree, a locked or marked worktree, a row with a Git operation or conflict, a broken row, or a row with unknown status. These rules apply even when callers bypass the TUI. A `Review` row requires its own explicit approval. `-f` is permitted only for a row whose uncommitted or untracked files were shown and whose discard choice was confirmed. `-D` is permitted only for a row whose unmerged branch deletion was explicitly confirmed. `--reap` is permitted only for a row whose process choice was confirmed.

Run `/opt/homebrew/bin/wt -C <repo> remove -y --foreground --format=json <absolute-worktree-path>` once per row, with only that row's confirmed flags. Worktrunk accepts paths for both named and detached worktrees. Per-row calls prevent a force flag from spilling over to another row and provide exact progress. Commands use separate process arguments, never a shell string. Do not use `rm -rf` or a Git removal fallback. Parse Worktrunk's JSON array and report `deleted`, `retained_unmerged`, `not_attempted`, or other branch outcomes distinctly from worktree removal success. If Worktrunk exits unsuccessfully, mark the row failed. If it exits successfully but returns malformed JSON, mark the outcome unverified, refresh the list, and continue with other confirmed rows.

After successful removals, run `git -C <repo> worktree prune` once per affected repository and rescan the dashboard. Read free disk space before and after the batch with `df -k /System/Volumes/Data`; report the measured change as an estimate, or omit it if either measurement fails. Append one JSON line per attempted removal to `~/.cache/wt-dash/removals.log` with timestamp, repo, path, branch, selected flags, exit status, branch outcome, and error if any. A logging failure appears in the action result and does not claim the removal was undone.

## State and failure handling

Only one cleanup operation may run at a time. The service retains the prepared plan and a snapshot of its checked facts, so a stale or reused plan is rejected. A scan error or unsupported Worktrunk schema blocks planning for the affected repository. A failed row does not block rows in other repositories; the final result lists successful, failed, and skipped rows. Refreshing after a partial batch shows actual current state, and selections for removed rows are cleared. The terminal remains usable after failures.

The current scanner can update row sizes while an action is open. Size and measurement time do not affect the removal plan's safety check. An external Git or Worktrunk process can still race with the final check; Worktrunk remains the authority for the actual removal and the dashboard reports its result rather than assuming success.

## Verification

Tests use an injected command runner and temporary repositories; they never remove a real worktree. Cover selection across sort/filter/refresh, preview cancellation, separate approvals for dirty content, ignored files, branch deletion and reaping, detached HEAD paths, main/busy/locked/marked/broken rejection in the core, stale-plan rejection, per-row flag isolation, malformed command output, partial batch failure, logging failure, prune preview scope, and terminal restoration. Run `bun test` and `bun run typecheck`. Manual terminal verification uses the existing dashboard and a disposable Git repository with disposable worktrees before any real cleanup.
